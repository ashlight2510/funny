GitHub Project Management: Code Review Process Using VSCode

As you work on a project, you'll realize how important code reviews are. Especially when collaborating with team members, they help maintain the quality of the code significantly. However, it can often feel overwhelming to know how to start a code review, right? So, this time, I’ve organized the process of managing GitHub projects and code reviews using VSCode.

1. Connecting VSCode with GitHub

Setting Up Your GitHub Account

To start the code review, you first need to connect VSCode with GitHub. If you don’t have a GitHub account, go to the official GitHub website and create one. Personally, I found that GitHub's community and various open-source projects are really beneficial.

Installing GitHub Extension in VSCode

You need to install a few extensions in VSCode to integrate with GitHub. You can install the "GitHub Pull Requests and Issues" extension, which makes code reviews much easier. After installation, log in with your GitHub account, and from there, it feels like a whole new world opens up.

2. Creating a Pull Request

Creating a Pull Request After Feature Development

Once feature development is complete, you need to create a Pull Request (PR). Select the branch you worked on in GitHub and click the "New Pull Request" button. It's important to write a good title and description for the PR, explaining briefly why the code you wrote is necessary.

Personally, I found that the PR description greatly helps team members in reviewing the code. It allows me to share the thought process behind my code.

3. Conducting Code Reviews

Reviewing Code in VSCode

Now that the PR is created, it's time for team members to start the review. In VSCode, you can easily review by opening the "GitHub Pull Requests" panel. When a team member leaves comments on the code, you can click on that part to make direct edits, and it's possible to exchange opinions.

From my experience, the ability to view and edit code directly in VSCode is really useful. Especially during code reviews, being able to reflect each other's feedback in real-time seems to enhance teamwork.

4. Reflecting Feedback and Merging

Reflecting Feedback

This is the stage where you reflect the feedback after the review is complete. After committing the modified code, you can update the same PR. During this process, you can communicate with team members to create better code.

Finally, once all the code is approved, click the "Merge" button! This will merge your code into the main branch. It’s truly a proud moment.

Conclusion

In this article, we explored the process of managing GitHub projects and code reviews using VSCode. I felt that code reviews greatly facilitate collaboration with team members and enhance code quality. If you have any questions, feel free to leave a comment. I think you should start with this!
