The Correct Procedure for Creating a Pull Request on GitHub

Have you ever felt overwhelmed about what to do when creating a Pull Request (PR) on GitHub? I remember when I first tried to learn this, I had a lot of doubts about how to get started. So, I’ve organized the methods I experienced. Through this article, you will be able to understand the process of creating a PR on GitHub more easily.

1. Prepare Your Changes

Create a Branch

First, before writing a PR, you need to prepare your changes. This is the most basic step, but I initially overlooked it and tried to create a PR right away, which caused me a lot of trouble. You need to create a new branch for the feature or bug fix you want to change.

git checkout -b my-feature-branch

You can create a new branch with this command. I found that this way, my work was neatly organized. Managing branches well seems to be the first step to making PRs smoother.

2. Write Commit Messages

Use Meaningful Messages

When committing your changes, it's important to write commit messages that clearly reflect the content. For example, instead of a generic message like "Fixed bug," it's better to write something specific like "Login page validation error fixed."

In my experience, writing commit messages this way greatly helps the person reviewing the code later. They can understand what happened at a glance.

3. Create a Pull Request

Write a PR Description

Now that you have committed all your changes, it’s time to create the PR. By clicking the "Pull Request" button on GitHub, you can create a new PR. The most important part here is the PR description.

In the PR description, you should detail what changes have been made and why these changes were necessary. If you neglect this, it can be difficult for the reviewer to understand. I remember when I first wrote a PR, I made the description too brief, and later the reviewer had many questions, which was challenging.

Request a Review

After writing the PR, you need to assign reviewers. Don’t forget to check this part. Having other colleagues review the parts I worked on allows for better code development.

4. Incorporate Feedback

Feedback is an Opportunity for Growth

After the reviewer checks the PR, they will provide feedback. At this time, you should accept it positively and incorporate any necessary changes. I was a bit scared when receiving feedback at first, but I realized that it was actually a great opportunity to improve the quality of my code.

After incorporating the feedback, you can commit again and add the updates to the PR.

Conclusion

I’ve summarized the correct procedure for creating a Pull Request on GitHub. It may feel complicated at first, but you will get used to it after a few tries. If you have any questions, please leave a comment. I think it would be good to start with this!
