Mastering Code Version Control on GitHub: A Beginner's Guide

When writing code, there will definitely be moments when you think, "Ah, I want to revert to a previous version!" Especially for beginners, concerns about version control can be overwhelming, so I decided to organize this information. Let's learn how to master code version control through GitHub!

What is GitHub?

The Difference Between Git and GitHub

First, it's good to clarify the difference between Git and GitHub. Git is a tool for code version control, while GitHub is a cloud service based on Git. In other words, you can use Git to work locally and then upload your work to GitHub to share with others. Understanding this point makes using GitHub much easier.

Why Should You Use GitHub?

Some might wonder, "Why should I use GitHub?" Personally, I think the most important reasons are collaboration and backup. Multiple people can participate in the same project simultaneously, and since it's stored in the cloud, it is safely backed up. I also found it really convenient when I first started using GitHub, as I could work together on various projects.

Getting Started with Basic Usage

Creating a GitHub Account

To use GitHub, you first need to create an account. Signing up is simple. Just go to the GitHub homepage and enter your email, username, and password. After signing up, a simple tutorial is provided, so it’s good to follow along. I was a bit nervous when I first signed up, but I quickly got used to it!

Creating a Repository

Once you've created your account, let's create a repository. A repository is a space to store your code files. You can create a repository by clicking the "New" button on the GitHub main page. At this time, you just need to enter a name and a brief description for your repository. When I created my first repository, it felt exciting and fulfilling!

Learning Basic Commands

Git Commands

To use Git, you need to know some basic commands. For example, git init is used to initialize a new repository, and git add . adds changed files to the staging area. You can record changes with git commit -m "message". Once I learned these commands, managing code became much easier.

Utilizing Branches

Using branches allows you to work on multiple tasks simultaneously. For example, when developing a new feature, you can create a separate branch to work on it and merge it with the main branch once completed. At first, I found the concept of branches confusing, but once I tried it, I realized how useful it is. Managing multiple tasks at once made my code cleaner.

Collaborating

Creating a Pull Request

To collaborate, you need to create a Pull Request. This allows you to compare another person's branch with your branch and suggest changes. It's really important to review each other's code and exchange feedback during this process. I was nervous when I first created a Pull Request, but later, receiving feedback from others and feeling my growth was very rewarding.

Utilizing Issues

You can manage problems or questions that arise during the project through Issues. It's really useful for communication with team members, so I recommend utilizing it. Thanks to this feature, my communication with team members has become much smoother.

Conclusion

We have looked at the basic ways to master code version control on GitHub. It may seem difficult at first, but as you use it, you will become more familiar with it. If you have any questions, please leave a comment. This is a great starting point!
