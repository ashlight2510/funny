GitHub에서 Pull Request를 작성하는 올바른 절차

혹시 GitHub에서 Pull Request(이하 PR)를 작성할 때 뭘 어떻게 해야 할지 막막했던 적 있어? 나도 처음에 이걸 배우려고 할 때, 어떻게 시작해야 할지 정말 고민이 많았던 기억이 나. 그래서 내가 경험한 방법들을 정리해 봤어. 이 글을 통해 GitHub에서 PR을 작성하는 과정을 좀 더 쉽게 이해할 수 있을 거야.

1. 변경 사항을 준비하자

브랜치 생성하기

먼저, PR을 작성하기 전에 변경 사항을 먼저 준비해야 해. 이건 기본 중의 기본인데, 내가 처음에 이걸 간과하고 바로 PR을 만들려다가 고생한 적이 있어. 변경할 기능이나 버그 수정을 위해 새로운 브랜치를 만들어야 해. 

git checkout -b my-feature-branch

이 명령어를 통해 새로운 브랜치를 만들 수 있어. 나도 이렇게 하니까 작업이 깔끔하게 정리되더라. 브랜치를 잘 관리하는 게 PR을 수월하게 만드는 첫걸음인 듯해.

2. 커밋 메시지 작성하기

의미 있는 메시지로

변경 사항을 커밋할 때는 그 내용이 잘 드러나도록 커밋 메시지를 작성하는 게 중요해. 예를 들어, "Fixed bug" 같은 일반적인 메시지보다는 "Login page validation error fixed"처럼 구체적으로 작성하는 게 좋아.

내 경험상, 이렇게 작성한 커밋 메시지가 나중에 코드를 리뷰하는 사람에게 큰 도움이 되더라고. 무슨 일이 있었는지를 한눈에 알 수 있으니까.

3. Pull Request 작성하기

PR 설명 작성하기

이제 모든 변경 사항을 커밋했으면, PR을 작성할 차례야. GitHub에서 "Pull Request" 버튼을 클릭하면 새로운 PR을 만들 수 있어. 여기서 제일 중요한 건 PR 설명이야.

PR 설명에는 어떤 변경 사항이 있는지, 왜 이 변경이 필요했는지 등을 자세히 적어야 해. 이걸 소홀히 하면 리뷰어가 이해하기 어렵거든. 내가 처음 PR을 작성했을 때는 설명을 간단히 했는데, 나중에 리뷰어가 질문을 많이 해서 힘들었던 기억이 있어.

리뷰 요청하기

PR을 작성한 후에는 리뷰어를 지정해야 해. 이 부분도 잊지 말고 체크해 봐. 내가 작업한 부분에 대해 다른 동료들이 리뷰를 해 주면, 더 나은 코드로 발전할 수 있으니까.

4. 피드백 반영하기

피드백은 성장의 기회

리뷰어가 PR을 확인한 후 피드백을 줄 거야. 이때는 꼭 긍정적으로 받아들이고, 필요한 수정 사항은 반영해야 해. 나도 처음에는 피드백을 받을 때 좀 겁이 났는데, 그게 사실 내 코드 품질을 높여주는 좋은 기회라는 걸 깨달았어.

피드백을 반영한 후에는 다시 커밋하고, PR에 업데이트 내용을 추가하면 돼.

마무리

이렇게 GitHub에서 Pull Request를 작성하는 올바른 절차를 정리해 봤어. 처음에는 복잡하게 느껴질 수 있지만, 몇 번 해 보면 익숙해질 거야. 궁금한 점은 댓글로 남겨 주세요. 이거부터 해 보면 좋겠어!
